01

产品定位

1.1 产品名称

荐知 · 个性化推荐智能体

1.2 目标用户

  • 每天刷资讯 / 短视频，感觉「越刷越窄」的内容消费者
  • 在电商里被「猜你喜欢」带着买、买完后悔的决策者
  • 想知道为什么被推、并且能关掉个性化的控制型用户

1.3 核心定位

市面推荐是黑盒信息流：推什么、为什么推、怎么停，用户说了不算。荐知是一层可解释、可纠偏、可关闭的推荐智能体，兴趣只建一次，资讯、视频、商品三条场景共用。

1.4 差异化

功能解释理由 + 负反馈立刻生效 + 多样性旋钮，而不是只给下一刷
数据一份兴趣档案跨场景复用，不用在每个 App 里重新养模型
体验主动说「这个主题有更新」，也能一键回到时间序
商业免费基础解释 / 会员跨场景与复盘 / 品牌内容位（明确标成广告，不伪装成推荐）

02

KANO 需求模型

2.1 判定规则

每条需求两题。正向：有这个功能你的感受；反向：没有这个功能你的感受。选项：很喜欢 / 理应如此 / 无所谓 / 能忍受 / 很不喜欢。对照经典 KANO 表归入 M 必备、O 期望、A 兴奋、I 无差异、R 反向、Q 存疑。

Better = (A+O)/(A+O+M+I)；Worse = −(O+M)/(A+O+M+I)。下表有效作答各 20 人，Q 不进分母。属性取人数最多的一类。

3.2 样本（演示）

定性 8 人（重度刷内容 3、网购决策 3、在意隐私 2）。定量有效 20 份。走查任务：「连续划掉 3 条不感兴趣后，下一条是否还在推同类。」演示结论：14/20 把「说了不感兴趣却还在推」选成最不能忍；11/20 愿意为「跨场景少重养兴趣」付费；只有 3/20 认为热度榜必需。

3.4 聚类

窄刷型 40%越刷越窄，最看重负反馈、多样性、解释
挑货型 30%怕被种草，最看重理由、订阅屏蔽、再来一组
可控型 20%要开关，最看重关闭个性化、档案、解释
随划型 10%低优先，热度榜和语音即可，不作为首版用户

3.5 核心画像

林窄 · 26 · 窄刷型

运营 · 杭州 · 每天刷 2 小时

目标：还能刷，但不要只剩一个主题。痛点：点过一次露营，后面三天全是帐篷。场景：对一条点「不感兴趣」，期望下一条换题。付费：19–39 元/月。

周挑 · 31 · 挑货型

产品 · 上海 · 每月网购 4–6 次

目标：少买错。痛点：猜你喜欢不说为什么，退货成本自己扛。场景：看一条推荐，先读理由再决定点不点。付费：39–69 元/月。

陈控 · 34 · 可控型

法务 · 北京 · 很少授权

目标：推荐可以有，但必须能关。痛点：找不到「关闭个性化」或关掉后又被打开。场景：出差时切到时间序。付费：愿为开关和导出档案付一次 29 元，不愿为皮肤付费。

P0 展开（Step3–5）

负反馈。方案：长按即选原因（看过 / 不喜欢这类 / 广告）；写入屏蔽表；下一刷过滤同类；24 小时内可撤销。流程：点不感兴趣 → 选原因 → 写入档案 → 下一刷不见同类。

档案。方案：三问生成初稿；行为只追加不覆盖；资讯、视频、商品读同一份；可导出、可删除。流程：三问或授权行为 → 结构化主题 → 三场景读取。

关闭个性化。方案：首页常驻状态；关闭后只按时间；再次打开要二次确认。流程：看见状态 → 一键时间序 → 推荐理由消失 → 需要时再打开。

解释。方案：每条一句：「因为你看过 / 订阅了 / 和这条相似」；没有依据就标成「热门」而不是「为你推荐」。流程：取依据 → 生成一句 → 用户可点进屏蔽该依据。

4.7 MVP 总流程

三问建档 P0每条给理由 P0不感兴趣立刻生效 P0可关个性化 P0冷启动离开纯热门 P1多样性旋钮 P1跨场景复用 P1主题提醒 P2每周复盘 P2

三款竞品 · 五层模型

六步：确认竞品 → 五层拆解 → 看迭代 → 定我方阶段 → 分层改 → 写出差异。

抖音推荐淘宝猜你喜欢通用对话模型
类型直接 · 内容信息流 · 成熟期直接 · 电商推荐 · 成熟期间接 · 用户拿它问「推荐点什么」
战略时长与广告成交与广告通用订阅，不经营推荐关系
范围强排序、弱解释、负反馈慢强成交、理由少、跨内容场景弱能解释，但不能记住并执行下一刷
结构单场景模型，兴趣出不了 App交易行为主导，内容兴趣进不来对话内记忆，没有推荐位
框架全屏上滑，控制项在设置深处信息流插在首页中部一问一答，没有旋钮
表现沉浸、少文字价格与销量优先一段话，没有「已屏蔽」状态

分年摘要（战略 / 范围）

竞品早年近年仍然不做
抖音关注 + 热门完播、互动、广告混排更紧把兴趣导出给别的场景；每条强制解释
淘宝买了又买首页猜你喜欢占比升高内容兴趣与商品兴趣显式分开给用户看
通用模型不能联网的问答能搜索后给清单负反馈作用于下一次信息流

我方机会

层机会
战略卖「可控的个性化」，不卖「更上头的时长」
范围解释、负反馈、开关、跨场景，四件竞品拆开做或藏起来
结构一份档案，三条场景来读
框架理由、不感兴趣、多样性、时间序都在卡片上，不进三级设置
表现状态可见：正在个性化 / 已关闭 / 已屏蔽这类

复盘：三家都不会把「用户可带走的兴趣档案」当成主产品。MVP 先做四项 P0，避免一上来模仿抖音的排序精度。

06

首页与核心链路

首页。顶栏：个性化开/关。中部四张卡：今日主题、已屏蔽、多样性、本周复盘入口。列表：每条推荐带一句理由和「不感兴趣」。底栏：首页 / 兴趣 / 屏蔽 / 我的。

打开首页看见开关状态三问或沿用档案刷到一条并读理由不感兴趣或再来一组下一刷按新约束出周末看复盘

体验流程与最小验证

阶段场景角色任务需求
进入第一次打开林窄、陈控看见开关，完成三问档案、关闭个性化
消费刷十条林窄、周挑读理由，决定点不点解释
纠偏出现不想看的三人不感兴趣，检查下一条负反馈
调节觉得太窄林窄把多样性调高旋钮
复盘周末陈控看这周推了什么、挡了什么周复盘 P2

为什么先做网页而不是 App

要验证的是「反馈有没有生效、理由信不信」，不是分发渠道。网页能在一周内让 8 个熟人完成同一任务：划掉 3 条，说出下一条为什么变了。App 上架和推送权限会把验证拖进渠道问题。

第 1 周 静态页 + 人工改下一条第 2–3 周 规则过滤原型第 4 周后再谈排序模型

一句话生意：用户为「推荐听得懂、停得掉」付会员；品牌内容单独买位置，并且永远标成广告。

09

自身五层（自上而下）

战略：可控的个性化范围：15 条收到 P0–P3结构：一份档案三条场景框架：卡片上完成纠偏表现：状态看得见
层要回答的荐知的答案
战略为谁、解决什么、怎么赚钱窄刷、挑货、可控三类；解决「推了无法停、也无法解释」；会员 + 明示广告位
范围做哪些M→P0 四项；O→P1 五项；A→P2 两项；I 延后；R 不做
结构数据怎么连档案中台；资讯 / 视频 / 商品只读不各养一份
框架人怎么走首页状态 + 列表理由 + 负反馈；兴趣与屏蔽两个二级页
表现长什么样少沉浸、多状态：开着个性化、已屏蔽、这是广告，三句话永远分得开

商业化

会员 · 约 60%跨场景记忆、多样性细调、每周复盘、导出档案
明示广告 · 约 25%单独位置，标「广告」，不进个性化理由
内容服务 · 约 15%主题清单、选购对照表，按次买
免费会员 29 元/月
理由与负反馈有有
关闭个性化有有
跨场景仅当前场景资讯 / 视频 / 商品
多样性档位两档五档 + 主题配额
周复盘与导出无有
广告有，每屏最多 1 条且标注无

不做的变现：把广告写成「因为你喜欢」；卖皮肤；用热度榜冒充个性化。分阶段：MVP 只验证有没有人愿意为「听得懂、停得掉」付钱；有留存后再开广告位。
