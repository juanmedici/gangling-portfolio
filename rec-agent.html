一

产品定位

1.1 产品名称

荐知 · 个性化推荐智能体

1.2 目标用户

  • 每天刷资讯和短视频、觉得越刷越窄的内容消费者
  • 被电商「猜你喜欢」带着下单、买完容易后悔的决策者
  • 想知道为什么被推、并且能关掉个性化的控制型用户

1.3 核心定位

区别于只优化下一刷时长的黑盒信息流。荐知是可解释、可纠偏、可关闭的推荐智能体：兴趣只建一次，资讯、视频、商品共用；每条写明依据；说不感兴趣，下一刷就生效。

1.4 核心差异化

  • 功能：负反馈立即生效、一句人话理由、多样性旋钮、时间序开关，覆盖「看懂—纠偏—停掉」整段，而不是只给下一条
  • 数据：一份兴趣档案跨场景复用，不用在每个产品里重新养模型
  • 体验：订阅主题有增量才开口；没有依据的内容标成热门，不冒充「为你推荐」
  • 商业：免费保留解释和开关；会员卖跨场景与复盘；广告单独占位并标注，不写进推荐理由

二

KANO 需求模型

2.1 问卷判定规则

每条需求两题。正向：拥有该功能的感受；反向：没有该功能的感受。选项：很喜欢 / 理应如此 / 无所谓 / 能忍受 / 很不喜欢。按经典对照表归入基本型 M、期望型 O、兴奋型 A、无差异 I、反向型 R、可疑 Q。

Better（SI）= (A+O)/(A+O+M+I)；Worse（DSI）= −(O+M)/(A+O+M+I)。下表每条有效作答 20 人。属性取人数最多的一类。反向型不硬套进四象限坐标。

3.2 样本与发现（演示）

  • 定性 8 人：重度刷内容 3、网购决策 3、在意隐私与开关 2。
  • 定量有效 20 份，用于把 15 条需求归类，不当作市场抽样。
  • 走查任务固定一句：「连续划掉 3 条不感兴趣，说出下一条为什么变了或为什么没变。」
  • 关键发现：14/20 最不能忍「点了不感兴趣下一条还是同类」；11/20 愿意为「换一个 App 不用重新养兴趣」付费；3/20 认为热度榜必需。

3.4 聚类结果

按「使用阶段、需求强度、付费意愿、使用频次」把演示样本分成 4 类。前 3 类是首版要服务的人，第 4 类不作为设计中心。

窄刷型 40% · 核心

特征：每天刷很久，主题越来越单一。

痛点：点过一次露营，后面几天全是帐篷。

最看重：负反馈、多样性旋钮、推荐理由。

挑货型 30% · 核心

特征：下单前会比较，讨厌被种草。

痛点：猜你喜欢不说依据，退货成本自己扛。

最看重：理由、订阅屏蔽、再来一组。

可控型 20% · 核心

特征：授权少，会找设置里的开关。

痛点：关掉个性化后又被打开，或者找不到入口。

最看重：时间序开关、档案可导出删除、理由。

随划型 10% · 低优先

特征：划过即可，不愿设置。

痛点：不明显。

最看重：热度榜、语音。首版不围绕他们做。

3.5 核心用户画像

林

林窄 · 窄刷型 · 26 岁

运营，杭州，每天信息流约 2 小时。目标：还能刷，但不要只剩一个主题。痛点：① 负反馈像没点过；② 不知道这周被收窄了多少；③ 设置藏得深。场景：对一条露营点「不感兴趣」，期望下一条换题，并看到「已屏蔽露营」。Top：负反馈、多样性、理由、周复盘、订阅屏蔽。付费：19–39 元/月，买「能停掉」。

周

周挑 · 挑货型 · 31 岁

产品，上海，每月网购 4–6 次。目标：少买错。痛点：① 推荐不写为什么；② 视频里看过的主题，商品流完全无关或反过来乱推；③ 一次点击就把长期兴趣锁死。场景：先读一句理由，再决定点不点；想多看两件时用「再来一组」，而不是改档案。Top：理由、跨场景、再来一组、订阅、冷启动。付费：39–69 元/月，买「少重养、少买错」。

陈

陈控 · 可控型 · 34 岁

法务，北京，很少授权行为数据。目标：推荐可以有，必须能关。痛点：① 开关不在首屏；② 关掉后仍出现「为你推荐」；③ 广告和兴趣混在同一句理由里。场景：出差时切到时间序，周末看一页「这周推了什么、挡了什么」，并可导出或删除档案。Top：关闭个性化、档案、理由、周复盘、负反馈。付费：一次 29 元买导出和开关记忆，不为皮肤付费。

需求 11 · 负反馈（M / P0）

Step1：用户明确表达不看这类，下一条仍是同类，信任直接掉。Step2：① 如何一次点击就写入屏蔽？② 如何在下一刷而不是明天生效？③ 如何允许 24 小时内撤销？Step3：长按选择原因（看过 / 不喜欢这类 / 这是广告）；写入屏蔽表；下 10 条过滤该主题；给出「已屏蔽」状态。Step4：DSI −0.80，全表缺失不满最高，P0 第一位。

flowchart TD
  A[点不感兴趣] --> B[选择原因]
  B --> C[写入屏蔽表]
  C --> D[下一刷过滤该主题]
  D --> E[界面显示已屏蔽]

需求 10 · 兴趣档案（M / P0）

Step1：资讯、视频、商品各自猜一遍，用户重复表达同一喜好。Step2：① 如何一次建立档案？② 如何让三个场景读同一份？③ 如何只追加、不偷偷覆盖？Step3：三问生成主题列表；行为只追加；可编辑、导出、删除；各场景读取前先看开关。Step4：DSI −0.75，没有它跨场景无从谈起。

flowchart TD
  A[三问或授权行为] --> B[生成主题列表]
  B --> C[写入兴趣档案]
  C --> D[资讯视频商品读取同一份]
  D --> E[用户可改可删]

需求 13 · 关闭个性化（M / P0）

Step1：开关在设置深处，关掉后仍出现「为你推荐」。Step2：① 如何让状态在首屏？② 如何关闭后只按时间？③ 如何再次打开要确认？Step3：顶栏常驻开/关；关闭后理由消失，列表按时间；打开需二次确认。Step4：DSI −0.70，可控型的底线。

flowchart TD
  A[首屏看见开关] --> B{是否关闭}
  B -->|关闭| C[时间序且不写为你推荐]
  B -->|保持| D[按档案推荐并给理由]
  C --> E[再次打开需确认]

需求 12 · 推荐理由（M / P0）

Step1：只有四个字「猜你喜欢」，用户无法判断该不该信。Step2：① 如何一句说清依据？② 如何避免编造？③ 如何从理由跳到屏蔽该依据？Step3：依据只来自看过、订阅、相似、热门四类；对不上就标「热门」；点击理由可屏蔽这一类。Step4：DSI −0.70，和负反馈绑在同一张卡片上。

flowchart TD
  A[取依据] --> B{能否对上档案}
  B -->|能| C[写一句因为你看过或订阅]
  B -->|不能| D[标成热门]
  C --> E[可点进屏蔽该依据]

需求 1 · 跨场景（O / P1）

Step1：短视频里确认过的主题，商品流毫无关系，或反过来用一次点击锁死。Step2：如何授权后迁移、且每个场景能单独关掉？Step3：档案分「全局主题」和「场景开关」；商品流默认可读视频确认过的主题，但可关。Step4：SI 0.70，会员理由，不进免费的全部能力。

flowchart TD
  A[在视频确认主题] --> B[写入全局档案]
  B --> C{该场景是否授权}
  C -->|是| D[商品流读取]
  C -->|否| E[该场景只用本场景行为]

需求 4 · 冷启动（O / P1）

Step1：新用户前 20 条全是大盘热门，个性化名不副实。Step2：如何三问内离开纯热门？Step3：三个主题选择；前 10 条至少 6 条命中；其余可标热门。Step4：SI 0.65、DSI −0.60，新用户第一分钟。

flowchart TD
  A[新用户] --> B[三问选主题]
  B --> C[前10条多数命中]
  C --> D[未命中的标热门]

需求 6 · 订阅与屏蔽（O / P1）

Step1：单条反馈太碎，用户其实想要的是主题级开关。Step2：如何让订阅和屏蔽都落在主题上？Step3：兴趣页列出主题，每项可订阅或屏蔽；屏蔽优先于订阅。Step4：与负反馈互补，P1。

flowchart TD
  A[打开兴趣页] --> B[选中主题]
  B --> C{订阅或屏蔽}
  C -->|订阅| D[提高该主题配额]
  C -->|屏蔽| E[该主题不再出现]

需求 7 · 多样性旋钮（O / P1）

Step1：用户感觉被收进一个主题出不来。Step2：如何自己把「更像」调成「更散」？Step3：首页一档旋钮；调高后相邻 5 条主题不重复。Step4：林窄的主诉求，P1。

flowchart TD
  A[拖动多样性] --> B[提高主题分散约束]
  B --> C[相邻条目不重复同一主题]

需求 5 · 再来一组（O / P1）

Step1：想多看两件，但一次点击不该改写长期档案。Step2：如何只影响当次会话？Step3：「再来一组」只加一个临时队列，不写入长期主题权重；会话结束丢弃。Step4：保护档案不被一次好奇污染。

flowchart TD
  A[点再来一组] --> B[生成临时相似队列]
  B --> C[不改长期档案]
  C --> D[会话结束丢弃临时队列]

需求 2 · 主动提醒（A / P2）

Step1：关心的主题有更新，用户要自己记得打开。Step2：如何只在有增量时开口，而不是天天催刷？Step3：仅订阅主题、仅有新条目、每天最多一条。Step4：SI 0.75、DSI −0.05，没有也不骂，P2。

flowchart TD

  B -->|有| C[推一条可点开]
  B -->|无| D[保持沉默]

需求 3 · 每周复盘（A / P2）

Step1：用户不知道这周被推向了哪、挡住了哪。Step2：如何一页说完？Step3：周末一页：曝光主题、屏蔽主题、开关是否用过、下一周建议只给一条。Step4：P2 留存，不进 v0.5。

flowchart TD

  B --> C[生成一页复盘]
  C --> D[给出一条下周建议]

4.6 延后与不做

  • R8 语音：无差异，播报成本高，延后。
  • R9 热度榜：无差异。若以后做，必须标「不是个性化」，不能占首页主列表。
  • R14 皮肤：反向，干扰看理由和开关，不开发。
  • R15 广告伪装：反向，商业上禁止。广告可以有，但不得使用「因为你喜欢」这句式。

5.7 五层对照

层抖音淘宝通用模型荐知的机会
战略时长与广告成交与广告通用订阅卖「听得懂、停得掉」，不卖更上头
范围下一条很强，解释弱商品卡很强，理由弱清单很强，没有流理由、负反馈、开关、跨场景四件放在一起
结构兴趣不出 App兴趣不出电商记忆停在聊天一份档案，三场景来读
框架上滑，控制在长按价格优先输入框卡片上同时有理由、不感兴趣、状态
表现沉浸少字价格最大一段话三句话永远分开：为你推荐 / 热门 / 广告

5.9 复盘

  1. 三家都没有把「用户可带走、可删除的兴趣档案」当成产品本身。
  2. 抖音强在下一条，弱在解释和停；淘宝强在成交，弱在依据；通用模型强在把话说清，弱在说完没有下一刷。
  3. 壁垒按 KANO 排：P0 是反馈生效、理由、开关、档案；P1 是跨场景和多样性；P2 是提醒和周复盘。排序精度不是首版要赢的点。
  4. 落地：v0.5 只做 P0；v1.0 做 P1；不在首版模仿抖音的完播模型。
  5. 长期：大平台不会把兴趣导出给用户当主功能。这个差异来自目标不同，不是来自多做一个皮肤。

三个人的差别

林窄

高频在纠偏和旋钮。先确认「点了有用」，再把相邻条目打散。

顺序：负反馈 > 多样性 > 理由。

周挑

高频在理由和再来一组。要多看，但不要改写长期档案。

顺序：理由 > 跨场景 > 再来一组。

陈控

高频在开关和复盘。出差用时间序，周末核对挡了什么。

顺序：关闭个性化 > 档案可删 > 周复盘。

8.2 为什么先网页，不先 App

App网页
周期双端数周，还要上架一页即可让人完成划掉 3 条
迭代发版规则可以当天改
验证的事渠道和留存反馈是否生效、理由信不信
习惯再装一个 App浏览器打开链接

  A[第1阶段 8人同一任务 人工改下一条] -->|换题能被说出来| B[第2阶段 规则过滤的网页]
  B -->|自助完成| C[第3阶段 才谈排序模型]
阶段做什么怎么做通过
1 人工验证「下一刷换题」值不值得做8 人打开静态列表，划掉 3 条，主持人换上下一条多数人能说出变了没有
2 网页验证不用人盯也能过滤屏蔽表 + 规则，理由四选一误推回潮下降
3 付费试验验证跨场景值不值得付钱免费只有当前场景，会员打开另一场景有人愿意为第二场景付一次

第一周做法

天动作
1找 8 个会刷信息流或网购的人，讲清任务只有划掉和口述
2–3每人划 3 条，记录下一条是否仍同类
4给一半人看「因为你看过」，给一半人只看「猜你喜欢」，问哪句能帮忙决定点不点
5问关闭个性化该放哪，记录有没有人找到
6问跨场景值不值 29 元，只记录愿不愿意，不劝
7整理：换题、理由、开关位置。决定进不进规则网页

这一周看的数

  • 能说出下一条变了没有的人 / 参加的人
  • 认为理由比「猜你喜欢」有用的人
  • 第一眼找不到开关的人
  • 愿意为第二场景付钱的人

8.3 一句话生意

给刷内容和网购的人，在「看一条、决定信不信、必要时停掉」的场景里，用档案、一句理由、立即生效的负反馈和首屏开关，把黑盒推荐变成说得清的推荐。钱来自会员（跨场景、复盘、导出）和单独标注的广告位，不来自把广告写成因为你喜欢。

要素解释
角色林窄、周挑、陈控
场景刷到不想看的；要买但不知道为什么被推；想暂时不要个性化
任务建档、读理由、负反馈、调多样性、关掉、周末看一页
商业免费保住解释和开关；会员卖跨场景和复盘；广告永远另一种句子

这样收钱的原因：用户气的是被骗和停不掉，不是不够好看；跨场景比每天催刷更适合做成订阅；广告若伪装成推荐，会直接打掉 P0 的信任，所以不能当主引擎。

十

信息架构

六种模式都用到：页签做全局，首页用便当盒和集中分发，兴趣与屏蔽用过滤和层级，我的用套娃。档案是底层数据，不单独占一个底栏，但从「我的」和「兴趣」都能走到。

10.1 原则

  • 一个页签一件事
  • 负反馈、理由、开关在首页就完成，不进三级设置
  • 导出、删除、会员收进「我的」
  • 首页四卡让人看见主题、屏蔽、多样性和复盘入口

10.2 六种模式

模式特征用在哪
页签并列切换首页 / 兴趣 / 屏蔽 / 我的
便当盒多块卡片首页四卡
集中分发一处到多处四卡进旋钮、屏蔽列表、复盘、开关说明
过滤列表加筛选兴趣按场景；屏蔽按原因
层级逐层兴趣 → 主题 → 这条依据从哪来
套娃一层套一层我的 → 档案 → 导出或删除 → 确认

首页

过滤。按原因看，可撤销。

套娃。档案、复盘、会员。

  • 中：四张卡
  • 下：推荐列表，广告卡样式不同

十一

商业化

① 会员 · 约 60%

稳定收入。卖跨场景、细档多样性、周复盘、导出。

② 明示广告 · 约 25%

免费用户看到单独广告位。句子只能是「广告」。

③ 内容服务 · 约 15%

主题清单、选购对照，按次买。

会员是底，广告和内容把人带去看会员。免费里已经有理由和开关，避免「不付钱就看不懂」。

11.2 会员分层

免费会员 29 元/月 或 199 元/年
理由与负反馈有有
关闭个性化有有
场景当前一个资讯、视频、商品
多样性两档五档，可给主题配额
周复盘与导出无有
广告有，每屏至多 1 条且标注无
flowchart LR
  F[免费 能看懂也能关掉] --> A[用满当前场景]
  A --> P{要不要第二场景}
  P -->|开通| S[会员]
  S --> R[续费看复盘和导出]

转化发生在「第二场景」，不发生在「把理由锁起来」。

看的数：从免费到会员的比例、次月还在不在、一个人一年付的钱是否盖得住把他请来的成本。目标只作规划：付费比例先看到有人真的付，再谈 8%。

11.3 广告

形式位置计费谁买
标注卡片列表中单独样式按展示或点击品牌
主题赞助兴趣页某个主题旁，标明赞助按周品牌
不做把广告写成因为你看过——

护栏：每屏最多一条；会员没有广告；广告模板与推荐模板不是同一套组件。

11.5 组合

  • 收入结构按会员、广告、内容来规划，避免只靠催刷
  • MVP 先看有没有人为第二场景付钱；有留存再开广告位
  • 单位经济以后再算；这一版先保证广告句式不破坏 P0
  • 风险：推荐数据敏感，广告不用「因为你的档案」做精准文案
结构、表格和图形的种类对齐示例作业（流程、思维导图、四象限、分年五层、路线、金字塔、信息架构、商业漏斗）。主题是个性化推荐智能体。问卷人数是课堂演示，用来把属性和系数算通。
